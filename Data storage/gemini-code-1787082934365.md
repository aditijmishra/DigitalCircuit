## 1. Fundamental Concepts of Data Representation

At the physical hardware layer, computer storage devices store information as discrete binary digits (bits) represented by voltage levels, magnetic polarities, or optical pits[cite: 1]. Higher-level data abstractions—such as text, signed integers, real numbers, graphics, and audio—are mapped onto these binary bit patterns using standardized encoding schemes[cite: 1].

### Key Definitions & Units
* **Bit (b):** The smallest unit of storage ($0$ or $1$)[cite: 1].
* **Nibble:** $4$ bits ($1$ Hexadecimal digit)[cite: 2].
* **Byte (B):** $8$ bits[cite: 2].
* **Word Size:** The native unit of data processed by a CPU in a single clock cycle (e.g., $32$-bit or $64$-bit architectures).
* **Storage Scales (IEC Binary Multiples vs. SI Decimal Multiples):**
  * **Decimal (SI):** $1 \text{ KB} = 10^3 = 1,000 \text{ Bytes}$
  * **Binary (IEC):** $1 \text{ KiB} = 2^{10} = 1,024 \text{ Bytes}$
  * $1 \text{ MiB} = 2^{20} = 1,048,576 \text{ Bytes}$
  * $1 \text{ GiB} = 2^{30} = 1,073,741,824 \text{ Bytes}$

## 2. Text & Character Encoding Schemes

### 2.1 ASCII (American Standard Code for Information Interchange)
* **Width:** 7 bits per character ($128$ total characters, range $0 \dots 127$)[cite: 1].
* **Structure:**
  * `0x00`–`0x1F` & `0x7F`: Non-printable control characters (e.g., `0x0A` LF, `0x0D` CR, `0x09` TAB, `0x00` NULL)[cite: 1].
  * `0x20`: Space character[cite: 1].
  * `0x30`–`0x39`: Digits `'0'` through `'9'`[cite: 1].
  * `0x41`–`0x5A`: Uppercase letters `'A'`–`'Z'`[cite: 1].
  * `0x61`–`0x7A`: Lowercase letters `'a'`–`'z'`[cite: 1].
* **Bit Manipulation Trick:**
  Converting between uppercase and lowercase requires toggling bit 5 ($2^5 = 32$)[cite: 1]:
  * `'A'` = `0100 0001` ($65$) $\leftrightarrow$ `'a'` = `0110 0001` ($97$)[cite: 1]

### 2.2 Extended ASCII & ISO-8859
* **Width:** 8 bits ($256$ code points)[cite: 1].
* **ISO-8859-1 (Latin-1):** Uses $128 \dots 255$ for Western European symbols (e.g., `Å, Ä, Ö, é`)[cite: 1].

### 2.3 Unicode Standard
Designed to unify characters from all human written languages and symbols into a single code space[cite: 1].
* **Code Points:** Represented as `U+XXXX` (from `U+0000` to `U+10FFFF`)[cite: 1].

#### Unicode Transformation Formats (UTF):
1. **UTF-8 (Variable-Length, 1 to 4 Bytes):**
   * **1-byte:** Compatible with 7-bit ASCII (`0xxxxxxx`)[cite: 1].
   * **2-byte:** `110xxxxx 10xxxxxx`[cite: 1]
   * **3-byte:** `1110xxxx 10xxxxxx 10xxxxxx`[cite: 1]
   * **4-byte:** `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx`[cite: 1]
   * *Advantages:* Space-efficient for ASCII-heavy text, backward-compatible with ASCII[cite: 1].
2. **UTF-16 (16-bit Code Units):**
   * Uses 2 bytes for basic multilingual plane (BMP) characters and 4 bytes (surrogate pairs) for supplementary characters[cite: 1].
3. **UTF-32 (Fixed 32 bits / 4 Bytes):**
   * Fixed length per character[cite: 1]. Simple indexing, but inefficient memory usage[cite: 1].

## 3. Real Numbers & Floating-Point Representation (IEEE 754)

Real numbers are represented in binary scientific notation:

$$V = (-1)^S \times M \times 2^E$$
[cite: 1]

### 3.1 IEEE 754 Single Precision (32-bit Standard)

| Field | Bits | Description |
| :--- | :---: | :--- |
| **Sign ($S$)** | 1 bit (bit 31) | $0 =$ Positive, $1 =$ Negative[cite: 1] |
| **Biased Exponent ($E$)** | 8 bits (bits 30–23) | Stored exponent with bias $127$ ($E = e + 127$)[cite: 1] |
| **Fraction/Mantissa ($F$)** | 23 bits (bits 22–0) | Fractional part of normalized mantissa $1.F$[cite: 1] |

```text
 31 30        23 22                               0
+--+------------+----------------------------------+
|S | Exponent E |           Fraction F             |
+--+------------+----------------------------------+
 1b    8 bits                23 bits
```[cite: 1]

### 3.2 IEEE 754 Double Precision (64-bit Standard)
* **Sign ($S$):** 1 bit
* **Biased Exponent ($E$):** 11 bits (Bias = $1023$)
* **Fraction ($F$):** 52 bits

### 3.3 Normalization & Formulas
* **Normalized Numbers ($0 < E < 255$):**
  $$\text{Value} = (-1)^S \times (1 + F) \times 2^{E - 127}$$[cite: 1]
  *(The integer bit $1$ before the radix point is implicit and not stored in memory)*[cite: 1].

### 3.4 Special IEEE 754 Encodings

| Exponent ($E$) | Fraction ($F$) | Meaning / Value |
| :---: | :---: | :--- |
| `0000 0000` | $0$ | Signed Zero ($+0.0$ or $-0.0$)[cite: 1] |
| `0000 0000` | Non-zero | Denormalized/Subnormal numbers ($(-1)^S \times 0.F \times 2^{-126}$)[cite: 1] |
| `1111 1111` | $0$ | Signed Infinity ($+\infty$ or $-\infty$)[cite: 1] |
| `1111 1111` | Non-zero | Not-a-Number (NaN)[cite: 1] |

## 4. Byte Ordering: Big-Endian vs. Little-Endian

When multi-byte data types (e.g., 32-bit integers) are stored in byte-addressable memory, endianness defines the order in which bytes are stored across memory addresses[cite: 1].

* **Big-Endian:** The **Most Significant Byte (MSB)** is stored at the lowest memory address[cite: 1]. Used in network protocols (TCP/IP) and legacy mainframe architectures[cite: 1].
* **Little-Endian:** The **Least Significant Byte (LSB)** is stored at the lowest memory address[cite: 1]. Used in x86, x86-64, and standard modern ARM hardware[cite: 1].

### Example: Storing `0x12345678` at Address `0x1000`

| Architecture | `0x1000` | `0x1001` | `0x1002` | `0x1003` |
| :--- | :---: | :---: | :---: | :---: |
| **Big-Endian** | `0x12` | `0x34` | `0x56` | `0x78` |[cite: 1]
| **Little-Endian** | `0x78` | `0x56` | `0x34` | `0x12` |[cite: 1]

## 5. Error Detection & Correction in Data Storage

Bit corruption can occur on physical storage media or during bus transfer due to electromagnetic interference, noise, or hardware degradation[cite: 1].

### 5.1 Parity Bit
Appends 1 bit to a data word[cite: 1].
* **Even Parity:** Total number of 1s in the codeword (including parity bit) is even[cite: 1].
* **Odd Parity:** Total number of 1s is odd[cite: 1].
* **Limitation:** Detects single-bit errors; fails if an even number of bits flip[cite: 1].

### 5.2 Cyclic Redundancy Check (CRC)
* Performs polynomial division on binary data blocks using a predetermined generator polynomial.
* Appends the division remainder (CRC tag) to the storage block for error detection.

### 5.3 Hamming Codes & Hamming Distance
* **Hamming Distance:** Minimum number of bit flips required to transform one valid codeword into another[cite: 1].
* **Hamming (7, 4) Code:**
  * Transmits 4 data bits using 7 total bits (adding 3 parity bits at positions $1, 2, 4$)[cite: 1].
  * Enables **Single Error Correction, Double Error Detection (SEC-DED)**[cite: 1].

## 6. Physical Storage Hierarchy

Memory technologies balance trade-offs between access speed, storage capacity, and cost per bit:

| Hierarchy Level | Technology | Access Speed | Relative Capacity | Volatility |
| :--- | :--- | :--- | :--- | :--- |
| **CPU Registers** | Flip-flops / Latches | $< 1 \text{ ns}$ | $< 1 \text{ KB}$ | Volatile |
| **L1/L2/L3 Cache** | Static RAM (SRAM) | $1 - 10 \text{ ns}$ | Megabytes ($\text{MB}$) | Volatile |
| **Main Memory** | Dynamic RAM (DRAM) | $50 - 100 \text{ ns}$ | Gigabytes ($\text{GB}$) | Volatile |
| **Secondary Storage** | Solid State Drives (NVMe / SSD) | $10 - 100 \mu\text{s}$ | Terabytes ($\text{TB}$) | Non-Volatile |
| **Tertiary Storage** | Magnetic HDDs / Tape | $5 - 15 \text{ ms}$ | Terabytes / Petabytes | Non-Volatile |

## 7. Exam Practice Questions & Solutions

### Practice Question 1
Convert the decimal floating-point number $-13.25_{10}$ into 32-bit IEEE 754 Single-Precision Hexadecimal format.

<details>
<summary><b>Click to View Solution</b></summary>

1. **Sign bit ($S$):** Negative number $\implies S = 1$[cite: 1].
2. **Binary Conversion:**
   * $13_{10} = 1101_2$
   * $0.25_{10} = 0.01_2$
   * Combined: $1101.01_2$
3. **Normalize:**
   * $1101.01_2 = 1.10101_2 \times 2^3$
   * Fraction $F = 10101000000000000000000_2$ (padded to 23 bits)[cite: 1].
   * Unbiased exponent $e = 3$.
4. **Biased Exponent ($E$):**
   * $E = 3 + 127 = 130_{10} = 1000\,0010_2$[cite: 1]
5. **Assemble 32-bit Word:**
   * `1` | `10000010` | `10101000000000000000000`
   * Hexadecimal grouping: `1100 0001 0101 0100 0000 0000 0000 0000`
   * **Final Answer:** **`0xC1540000`**
</details>

How is the UTF-8 string `'A'` represented in memory compared to its UTF-16 and UTF-32 representations?
